COMO SE CONFIGURAN LOS ERRORES

web_err_cfg.h

configuracion

Los errores se definen en un solo archivo: web_err_cfg.h. Una linea por error, asociada a su ID:

X( 101, AP1_C1, ERR_ALARMA, 0, (al_w & 0x0001u), "al_w c1_hp", "Alta presion circuito 1", c_hp[0]) \
X( 108, FILTRO, ERR_AVISO,  5, (dp_filt > 250u),  "dp_filt",    "Filtro de aire sucio",     dp_filt)
  • ID: numero unico que ve el usuario.
  • NOMBRE: identificador corto (sin comillas).
  • SEVERIDAD: ERR_INFO, ERR_AVISO, ERR_ALARMA, ERR_CRITICO.
  • RETARDO: segundos que debe mantenerse la condicion antes de activarse (filtra rebotes).
  • CONDICION: expresion C con tus variables, verdadera cuando hay error.
  • "VARIABLES": IDs web que la activan (se muestran con su valor en vivo si estan en la pagina errores).
  • "DESCRIPCION": texto para el usuario.
  • VALOR: expresion que se guarda en el historico al activarse.

Para añadir un error: añade una linea (hasta 32). No hay que tocar HTML ni la tabla de variables. Los cambios en variables en vivo de la columna VARIABLES requieren que esa variable tenga PG_ERR en su campo de paginas en web_vars.c.

Como se usa
/* web_err_cfg.h */
#define WEBERR_NOW()  (rtc_epoch)      /* hora UNIX para fechar los errores (cambia por tu RTC) */
#define WEBERR_LIST(X) \
  X( ID, NOMBRE, SEVERIDAD, RETARDO_s, (CONDICION), "VARIABLES", "DESCRIPCION", VALOR) \
  ...
// web_err.c evalua las condiciones cada segundo (WebErr_Tick1s, llamada desde network.c)
// y lleva: err_act (activos), err_una (sin reconocer), err_cnt[], err_last[], err_hist[]
